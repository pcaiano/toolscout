Zapier expands Next Gen Zaps with branching, recovery and agentic management

Zapier has now detailed a broader redesign of its automation model, adding richer workflow logic and agent managed recovery to the MCP based creation experience announced earlier this month.

What changed

Zapier's Next Gen Zaps are becoming a deeper execution model, not just a new way to describe automations to an AI client. The platform can now branch and rejoin flows, work through larger lists, continue after individual errors, pause for human input and use an agent to diagnose failed runs. MCP remains an entry point, but the more consequential change is what the workflow can do after it has been created.

Zapier also introduced agentic management for these workflows. A monitoring agent can watch runs, diagnose failures and either apply or propose a fix. Users can still build from supported MCP clients such as ChatGPT, Claude and Cursor, or work directly in Zapier with natural language, code and a visual canvas.

Why it matters

This moves the comparison with other automation platforms away from connector count alone. Buyers running complex operational processes should now look at branching, recovery, long-running execution, human checkpoints and repair workflows. Those are the areas where a simple automation product starts to overlap with more technical orchestration tools.

The self healing element is also significant. Automation platforms have traditionally helped users build workflows but left monitoring and repair largely to the operator. An agent that can diagnose a failed run and propose a repair moves some of that operational burden into the platform itself.

Buyer takeaway

Next Gen Zaps is still early access, so capability and production readiness should be judged separately. Test failure recovery, auditability, change control and human intervention with a real workflow before treating the new model as a replacement for established production automations.
