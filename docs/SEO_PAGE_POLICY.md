# SEO Page Quality Policy

ToolScout must not publish a page merely because an intent has search demand.

A candidate must have:

- a distinct user problem;
- at least two genuinely relevant tools or a useful comparison;
- original recommendation logic;
- transparent pricing/feature context where available;
- a clear reason the page is useful beyond merchant copy;
- no copied merchant descriptions as the primary content;
- no doorway-page variants created only by swapping keywords.

## Publishing states

`candidate` → discovered automatically

`review` → quality checks passed and awaiting approval

`published` → explicitly approved

`rejected` → insufficient value or duplication

Automation may discover and score candidates, but it must not silently publish new SEO pages.

This protects the project from scaled-content and thin-affiliate patterns while still allowing the site to scale when it has genuine utility.


## Editorial software surface rule

ToolScout should use a hybrid editorial and structured model.

- Keep factual fields, schema markup, internal links, pricing context, capabilities and other machine-readable signals.
- Tool cards and profiles must add a short original ToolScout view based on supported catalog evidence rather than presenting only badge lists or raw attributes.
- Comparison pages must add a concise prose conclusion that explains the practical trade-offs without forcing a universal winner.
- The editorial layer must add interpretation, not unsupported claims. It should help a human buyer understand fit while leaving the structured facts intact for search engines and answer engines.
- All generators that create or refresh software profiles or comparisons must preserve this rule.
- ToolScout editorial content is English only and must not use em dashes or en dashes.
